## 1. コンセプト

- [決定] 和風。刀を持った主人公が、城下町 → 屋根 → 城と攻め上がる。
- [決定] 参考：速度感はソニックアドベンチャー、立体的な移動は SEKIRO、戦闘のテンポはハイテンポな SEKIRO。
- [決定] メイン要素はスピード感＋爽快感。**タイムアタック寄り**。
- [決定] 体験の目標は「カッコよくプレイできた自分が好き」。上手い・下手の差が、見た目とタイムにはっきり出る。
- [決定] 走り続けるのが基本。失敗の格好悪さは、ゲームオーバーではなく、よろけ・減速・着地崩れのモーションで見せる。

### 設計の柱

1. **止まらない**：失敗しても流れは切れない（最低保証速度がある）
2. **上手いほど速い**：Perfect が続くほど速度段階が上がり、タイムが縮む
3. **上手いほど格好いい**：Perfect と Miss は専用モーションにして、見た目で差を出す

- [提案] タイムアタック寄りにすると、ゲーム性が上がるかわりに一般性（誰でも遊べる度合い）が下がる〔桜井#146〕。そこで役割を分ける。
  - 「止まらない走り」と「失敗のないトドメ」は、誰でも最後まで行ける床
  - 「タイム」と「Perfect」は、上手い人が目指す天井
  - 初心者と上級者を同時に満足させる考え方は〔桜井#011〕と同じ。

## 2. 技術前提

- [決定] エンジンは Unreal Engine 5。（[未決] バージョン）
- [決定] **60fps 前提**。フレーム数（F）で書く値は、すべて 60fps 基準。
- [決定] キャラは **UE5 標準マネキン（Manny / Quinn）** のスケルトンを基準にする。本番のキャラは、後からこのスケルトンへリターゲットする。
- [決定] 移動は**基本コード制御**（Character Movement）。ルートモーションは一部のアクションだけ使う（§9.1）。
- [決定] モーションのタイミング（判定F・接地Fなど）は、アニメーションアセットに埋め込まない。**Data Table の別データ**として持つ（§9.2）。
- [提案] **実装は C++ を中心にする。**
  - Blueprint は .uasset（バイナリ）なので、AI は直接読み書きできず、差分も追えない。
  - Blueprint は、C++ クラスを継承して見た目やアセットを割り当てる用途だけにする。
- [提案] Data Table は CSV / JSON から読み込める形にする。テキストで管理できるので、人も AI も編集できる。
- [提案] 入力は Enhanced Input を使う（長押しは Hold トリガー）。

## 3. 速度システム

- [決定] 速度は段階で持つ。

| 段階 | 名前 | パラメーター |
|---|---|---|
| 0 | 最低保証 | 【最低保証速度】(SpeedTierMin) = ○ |
| 1 | 巡航（スタート時） | 【巡航速度】(SpeedTierCruise) = ○ |
| 2 | 加速 | 【加速速度】(SpeedTierBoost) = ○ |
| 3 | 最高 | 【最高速度】(SpeedTierMax) = ○ |

- [決定] Perfect が 【加速に必要なPerfect連続数】(PerfectChainToTierUp) = ○ 回続くと、1段上がる。
- [決定] Great・Good では段階を維持する。ただし Perfect の連続カウントはリセットする。
- [決定] Miss・被弾で1段下がる。**段階0より下には落ちない＝止まらない。**
- 段階が変わるときの変化時間
  - 【段階アップの加速時間】(TierUpBlendTime) = ○秒
  - 【段階ダウンの減速時間】(TierDownBlendTime) = ○秒
- 根拠
  - 〔桜井#065〕気持ちよさには反対の要素も入れる（高速なら、遅くなる条件）。減速そのものが罰になる。
  - 〔桜井#116〕罰の重さより、再開の速さの方が効く。
  - 〔心理〕損失回避：稼いだ速度を失うのは、同じ量を得られないより強く感じる。なので下げるのは1段までにする。
- [提案] **最高段階のときだけ届く足場（近道）**をステージに置く。タイムアタックでは、通れるルートの差がそのまま腕の差になる（〔桜井#065〕エアライドの「踏み切り地点を探す遊び」と同じ考え）。

## 4. 移動アクション

### 4.1 走る

- [決定] スティックを前に倒すだけで走る。ボタンは要らない。
- [提案] スティックの倒し具合で速度は変えない。倒していれば、今の段階の速度で走る。タイムアタックで倒し具合の微調整までは求めない。
- 【走り始めの加速時間】(RunStartAccelTime) = ○秒
- 【旋回速度】(TurnRate) = ○deg/秒（段階ごとに設定できる形にする）

### 4.2 ジャンプ

- [決定] ジャンプキーで跳ぶ。
- 初速を与えて、毎フレーム一定の重力をかけるのが基本〔桜井#037〕。
  - 【ジャンプ初速】(JumpVelocity) = ○
  - 【上昇中の重力】(GravityRise) = ○
  - 【落下中の重力】(GravityFall) = ○（[提案] 上昇より落下を速くすると力強く見える）
- 【空中制御の強さ】(AirControl) = ○
- 走りのときの、ジャンプの横方向の速度は今の段階の速度を引き継ぐ。
- [提案] 屋根の端
  - 走りでは端から落ちる（屋根渡りが中心の遊びなので）。
  - 弾き・回避・斬り抜けの動作中は落ちない。
  - 〔桜井#102〕崖から無条件に落とすのは多くの場合よくない。アクションごとに落ちる/落ちないを決める。

### 4.3 壁走り

- [決定] **長押し**で壁走りする。
- [未決] どのボタンを長押しするか。
  - [提案] ジャンプキー。壁に向かって跳んで押し続けている間は壁走り、離すと壁から跳ぶ（壁ジャンプ）。
  - この場合、ジャンプの「長押しで高さを調整する」仕組みは入れない。
- [提案] **離すタイミングに意味を持たせる。**
  - 〔桜井#051〕長押しだけでは遊びになりにくいが、押す/離すの「切り替え」は遊びになる。
  - 離した位置で跳んだ先が変わるように配置する（早すぎると届かない、遅すぎると壁が終わって落ちる）。
- パラメーター
  - 【壁走りの最大時間】(WallRunMaxTime) = ○秒
  - 【壁走り中の速度倍率】(WallRunSpeedScale) = ○
  - 【壁走り中の落下速度】(WallRunFallSpeed) = ○
  - 【壁ジャンプの初速（壁から離れる向き）】(WallJumpOutVelocity) = ○
  - 【壁ジャンプの初速（上向き）】(WallJumpUpVelocity) = ○
  - 【壁走りを始められる最低速度】(WallRunMinSpeed) = ○
  - 【壁走りを始められる、壁との角度の範囲】(WallRunAngleTolerance) = ○deg

### 4.4 縁につかまる・よじ登る（QTE）

- [決定] 縁につかまる・登るは QTE にする。
- 流れ：ジャンプが届かずに縁の判定に入る → 自動で縁につかまる → 登りの QTE が出る。
- 結果
  - Perfect：一気に駆け上がる（段階を維持し、連続カウント+1）
  - Great・Good：普通に登る
  - Miss：もたついて登る（1段下がる）
- [提案] 縁につかまれること自体が、ジャンプの小さな失敗の救済になる。奈落に落とさず、流れを保てる。
- ルートモーションを使う（§9.1）。

## 5. 高速QTE

### 5.1 基本

- [決定] **トリガー**（ステージに置くボリューム）で出す。
- [決定] **押すタイミング**を重視する。判定は「ボタンが合っているか」＋「Perfect / Great / Good / Miss」。
- [決定] ボタンの表示は早めに出す。判定のタイミングは、リングが縮む・刀が光るなどで読ませる。
- [提案] QTE のボタンには普段のアクションのボタンを使う（跳ぶ＝ジャンプ、斬る＝攻撃）。
  - 「指示に従った」より「自分が跳んだ・斬った」と感じやすく、成功を自分の手柄と感じやすい。
  - ボタンの種類を絞れるので、キーコンフィグに対応するアイコンの数も減る〔桜井#085〕。
- 判定の幅（判定タイミングから前後何Fか）
  - 【Perfect判定幅】(QTEWindowPerfect) = ±○F
  - 【Great判定幅】(QTEWindowGreat) = ±○F
  - 【Good判定幅】(QTEWindowGood) = ±○F
  - 判定幅の外で押した・違うボタンを押した・押さなかった → Miss
- [提案] Perfect から離れるほど急に損をする作りにする〔桜井#026〕。判定幅は狭めから始めて、テストしながら広げる。
- 【表示してから判定までのF】(QTELeadFrames) = ○（リングが縮む時間）
- [提案] 表示遅延の補正をオプションに入れる：【入力タイミング補正】(InputLatencyOffset) = ±○ms
  - 〔桜井#008〕表示遅延は作り手でも気づきにくく、反応の良いゲームを台無しにする。

### 5.2 連鎖

- [決定] 屋根から屋根への跳躍や、敵を続けて斬り抜ける場面などで、複数の入力をリズムでつなぐ。
- 連鎖の中身（ボタンの並び・間隔）は、トリガーごとに Data Table で決める。
  - 【連鎖の入力間隔】(QTEChainInterval) = ○F
- [提案] 連鎖の途中で Miss しても連鎖は止めず、残りの入力は続けられるようにする（流れを切らない）。

### 5.3 判定ごとの結果

- [決定] 専用モーションは **Perfect と Miss の2つだけ**作る。Great と Good は基本モーションのまま、ヒットストップ・カメラ・エフェクトで差をつける。

| 判定 | モーション | ヒットストップ | カメラ・エフェクト | 速度 |
|---|---|---|---|---|
| Perfect | **専用**（決めポーズ＋フォロースルー） | 長め【Perfect時の停止F】(HitStopPerfect) = ○ | 寄る・残像・刀が光る | 連続で1段上がる |
| Great | 基本 | 標準【Great時の停止F】(HitStopGreat) = ○ | 標準 | 維持 |
| Good | 基本 | 短め【Good時の停止F】(HitStopGood) = ○ | 控えめ | 維持（連続はリセット） |
| Miss | **専用**（着地崩れ・よろけ・もたつき） | なし | 引く・揺れる | 1段下がる |

## 6. 戦闘

- [決定] **走りながら戦う**のが基本。
- [決定] 弾きと回避は QTE ではなく、**キー入力**で行う（敵のモーション・効果音・光を読む）。
- [決定] 体幹（HP 以外の崩しゲージ）は基本的に入れない。
- [未決] 足を止めて戦う場面を入れるか。
  - [提案] 土台には入れない。走りながらの戦闘をプロトで遊んでから決める。
- [未決] 走りながら攻撃する（斬り抜け）ときの入力方法。
- [提案] **戦闘の結果も速度段階につなげる**（戦闘の上手さがタイムに直結する）。

| 行動 | 結果 |
|---|---|
| ジャスト弾き | 敵が崩れて、そのまま斬り抜けられる。Perfect の連続+1 |
| 普通の弾き | 防ぐだけ。速度は維持、連続はリセット |
| 回避 | 速度は維持 |
| 被弾 | よろけて1段下がる |
| 斬り抜け（雑魚） | 一撃で倒す。速度は維持 |

- [提案] リスクとリターン〔桜井#006〕
  - 敵を避けて通る：安全だが加速しない
  - 斬り抜け・ジャスト弾き：被弾の危険はあるが加速できる
  - つまり敵は「障害物」であり、同時に「加速装置」でもある。
- パラメーター
  - 【弾きの受付F】(ParryWindow) = ○
  - 【ジャスト弾きの受付F】(ParryJustWindow) = ○
  - 【回避の無敵F】(DodgeInvincibleFrames) = ○
  - 【回避の総F】(DodgeTotalFrames) = ○
  - 【被弾よろけの総F】(StaggerTotalFrames) = ○

## 7. ボスのトドメ

- [決定] **失敗のないご褒美演出**にする。入力は1回で、タイミングだけを見る。
- [決定] Perfect なら専用の決め、それ以外なら標準のトドメ。どちらでもボスは倒せる。
- 根拠
  - 〔桜井#231〕ムービー中の QTE は嫌われがち。
  - 〔心理〕ピーク・エンドの法則：体験の評価は、一番盛り上がった所と終わり方で決まりやすい。
  - 〔桜井#009〕トドメは「ギュッとしてパッと解消」の「パッと解消」の瞬間。ここで新しいストレスを入れない。
- [提案] 納刀の鍔鳴りの瞬間を判定タイミングにする。Perfect なら、鍔鳴りと同時に敵が崩れ落ちる。
- 撃破の瞬間に、短い停止＋フラッシュを入れる〔桜井#003〕。
- 再戦したときは、短縮版かスキップを用意する〔桜井#231〕。
- [未決] ボス戦そのものの形式（足を止めて戦うか、追いかけながら戦うか）。

## 8. タイムアタック

- [提案] **タイマーは操作している時間だけを数える。**
  - ヒットストップ・Perfect の決め・トドメの演出中は止める。
  - Perfect はヒットストップが長いので、止めないと「上手いほどタイムで損をする」ことになる。
- [提案] **すぐリトライできるようにする**：ボタン1つで、チェックポイントか最初から始め直せる。
  - 【リトライから操作が戻るまでの時間】(RetryResumeTime) = ○秒以内〔桜井#116〕
- [提案] 奈落に落ちたらチェックポイントに戻る（タイムは止めない）。これが唯一の「止まる」失敗。
- [提案] 運の要素は入れない。敵の動きも QTE の出方も、毎回同じにする〔桜井#187〕（腕だけで決めたい勝負にランダムは向かない）。
- [提案] 次のランクまでの差を見せる。例：「Sランクまで あと1.2秒」〔桜井#023 ご褒美は目の前に吊るす〕
- [提案] ランキングは順位ではなく、全プレイヤーの中での位置（上位○%）で見せる〔桜井#168〕。※土台の範囲外
- [提案] ゴースト（自分のベスト走行の再生）。※土台の範囲外。ただし、入力と位置を後から記録できる作りにしておく。

## 9. アニメーション

### 9.1 ルートモーション

- [決定] 基本はコードで動かし、一部だけルートモーションを使う。
- [提案] 振り分け
  - **ルートモーションを使う**：縁につかまる・よじ登る、着地崩れ、被弾よろけ、トドメ
  - **使わない（コードの速度で動かす）**：走り、ジャンプ、壁走り、弾き、回避、斬り抜け
  - 考え方：移動量を速度段階で決めたいものはコード、移動量そのものが演技になるものはルートモーション。

### 9.2 タイミングデータ（Data Table）

- [決定] 判定のタイミングは、アニメーションとは別のデータで持つ。
- 構造の案（行構造体 `FMotionTimingRow`）

| 列 | 型 | 意味 |
|---|---|---|
| RowName | Name | モーションの ID（例：`Ledge_Climb_Perfect`） |
| Anim | AnimSequence / Montage の参照 | 再生するアニメーション |
| BaseRow | Name | 判定別の版の場合、元になる基本版の ID |
| TotalFrames | int | 総フレーム数 |
| BranchFrame | int | 判定で分かれるフレーム（入力のフレーム） |
| ContactFrame | int | 接地・ヒットのフレーム |
| CancelFrame | int | 次の行動に移れるフレーム |
| UseRootMotion | bool | ルートモーションを使うか |
| HitStopFrames | int | ヒットストップのフレーム数 |

- [提案] **Perfect 版は TotalFrames・ContactFrame・CancelFrame を基本版と同じにして、キーポーズとフォロースルーの中身だけを差し替える。**
  - タイミングが同じなので、ゲーム側の判定や移動に影響しない。後から差し替えたり追加したりできる。
  - BaseRow と値がずれていたら、起動時に警告を出す。
  - 〔桜井#049 / #148〕入力の1フレーム目で大きくポーズを変え、振り抜きは1フレームで一気に。Perfect 版は1フレーム目をさらに極端にする。
  - 〔桜井#223 / #077〕目に残るのはヒットの瞬間のポーズで、印象を決めるのはフォロースルー。差し替えるのはこの2か所。
- [提案] 上半身だけ決めポーズを差し替える場合は、AnimBP の Layered Blend per Bone を使う（下半身＝走りのベース、上半身＝差し替え）。

### 9.3 モーションリスト（土台用。仮モーションで可）

| ID | 内容 | ルートモーション | 判定別の版 |
|---|---|---|---|
| Run | 走り（段階ごとに再生速度を変える or ブレンドスペース） | なし | — |
| Jump_Start / Jump_Air / Land | ジャンプ・空中・着地 | なし | — |
| Land_Stumble | 着地崩れ（Miss 共通） | あり | Miss 専用 |
| WallRun_L / WallRun_R | 壁走り（左右） | なし | — |
| WallJump | 壁ジャンプ | なし | — |
| Ledge_Grab | 縁につかまる | あり | — |
| Ledge_Climb | よじ登る（基本） | あり | Perfect / Miss |
| Leap | 屋根跳躍 QTE（基本） | なし | Perfect（Miss は Land_Stumble） |
| Slash_Through | 斬り抜け（基本） | なし | Perfect |
| Parry / Parry_Just | 弾き / ジャスト弾き | なし | — |
| Dodge | 回避 | なし | — |
| Hit_Stagger | 被弾よろけ | あり | — |
| Finisher | トドメ（基本） | あり | Perfect |

- Miss のモーションは、QTE の種類ごとには作らず共通にする（着地崩れ・よろけ・もたつき登り）。失敗の大きさで2段階くらいに分ける〔桜井#140〕。
- 土台では、マネキン用の仮モーションで構わない。総F・判定Fを Data Table に入れておけば、後で本番のモーションに差し替えてもゲーム側は変わらない。

## 10. カメラ

- [決定] キャラの後ろからの三人称が基本。
- [決定] FOV などを使って、スピード感を全力で演出する。
- [決定] 壁走り中はカメラを傾ける。
- パラメーター
  - 【速度段階ごとのFOV】(FOVPerTier) = ○ / ○ / ○ / ○
  - 【FOVが変わる時間】(FOVBlendTime) = ○秒
  - 【壁走り中のカメラの傾き】(WallRunCameraRoll) = ○deg
  - 【傾きの補間時間】(WallRunRollBlendTime) = ○秒
- [提案] 注視点をキャラに直接くっつけない〔桜井#061〕。
  - 進む方向の少し先を見る：【注視点の先読み距離】(CameraLookAhead) = ○（速度に合わせて伸ばす）
  - 縦の追従は弱めにして、ジャンプの高さが分かるようにする。
- [提案] スピード感の補助：モーションブラー、スピードライン、風切り音。
  - 【スピード演出の強さ】(SpeedFXIntensity) = ○
- [提案] **酔い対策を最初からオプションに入れる**〔桜井#128〕。
  - カメラの傾きの強さ、FOV 変化の強さ、画面揺れのオン/オフ。
  - 高速移動・カメラの傾き・FOV の変化は、どれも酔いやすくなる要素。

## 12. 土台（プロトタイプ）の範囲

### 作るもの

- 屋根ルート1本（30〜60秒）。次をすべて含める。
  - 走る、ジャンプ
  - 壁走り（1か所以上）
  - 縁につかまる（1か所以上）
  - 屋根跳躍の連鎖 QTE（1か所）
  - 最高段階でしか通れない近道（1か所）
- 雑魚1種類（斬り抜け・弾き・回避の確認用）
- トドメのテスト1回（ボスの代わりにダミーを置く）
- 仕組み：速度段階、QTE（トリガー・判定・連鎖・判定ごとの結果）、カメラ、タイマー、即リトライ
- Data Table 一式（パラメーター、モーションのタイミング、QTE トリガーの定義）
- デバッグ表示
- キャラは UE5 マネキンと仮モーション。ステージは灰色の箱のブロックアウト。

### 作らないもの

- 本番のアート・モーション・サウンド
- UI の作り込み（デバッグ表示があれば十分）、メニュー、セーブ
- ランキング、ゴースト
- ボス戦の本体、足を止める戦闘
- ストーリー、演出ムービー

### 完成の条件

- 灰色のコースを、最初から最後まで止まらずに走り切れる。
- Perfect を続けると速度段階が上がり、タイムが縮むのが体感できる。
- Miss・被弾で1段下がるが、止まらない。
- 判定ごとのモーションの分岐が、Data Table のタイミング通りに動く。
- Data Table の値を変えると、ゲームを再起動せずに挙動が変わる。
- 60fps で動く。
