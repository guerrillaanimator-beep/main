# CLAUDE.md

## このプロジェクト

**Sengoku Run**（和風ハイスピード剣戟アクション）。Unreal Engine 5.8.4 / C++。
仕様は `docs/spec_core.md` にある。**作業を始める前に必ず全部読む。**

## 仕様の扱い

- **[決定]** には従う。
- **[提案]** はそのまま実装してよい。変えたいときは、先に理由を添えて確認する。
- **[未決]** は自分で決めない。質問する。
- 仕様にない判断が要るときは、勝手に決めず、選択肢とおすすめを出して確認する。

## 実装のルール

- **C++ を中心に書く。** Blueprint は、C++ クラスを継承してメッシュやアニメーションを割り当てる用途だけにする。
- **数値をコードに直接書かない。** 調整する値はすべてデータに出す。
  - CSV ファイルを正本にする（`Content/Data/*.csv`）。人も AI もテキストで編集できるようにするため。
  - ゲームの実行中に CSV を読み直して反映できる仕組みを作る（コンソールコマンドなど）。
  - パラメーター名は、仕様書の `(EnglishName)` をそのまま使う。
- **60fps 前提。** 仕様書でフレーム数（F）で書かれた値は、60fps 基準で解釈する。
- **モーションのタイミングはデータから読む。** アニメーションアセットに埋め込まない（仕様書 §9.2 の `FMotionTimingRow`）。
- キャラは UE5 標準マネキン（Manny / Quinn）。モーションは仮のもので構わない。
- 入力は Enhanced Input を使う。

## .uasset / .umap について

- .uasset や .umap はバイナリなので、直接編集しない。
- エディタでの作業（アセットの作成・割り当て、レベルの箱組みなど）が必要なときは、**ユーザーに手順を書いて頼む**。
- コースの箱組みはユーザーがエディタで行う。こちらは、そのために置く部品（QTE トリガー、リスポーン地点、壁走りできる壁、縁など）を C++ のアクターとして用意する。

## 進め方

- **マイルストーン単位で止まる。** 1つ終わったら、次の順で報告して止まる。
  1. 作ったもの
  2. ビルドが通ったこと
  3. ユーザーがエディタで確かめる手順（どのレベルを開き、何を押すと、どうなれば成功か）
  4. このマイルストーンで追加した調整用パラメーター
- ユーザーがエディタで触って OK を出すまで、次のマイルストーンに進まない。
- マイルストーンが終わるたびに git commit する。

## ビルド

- C++ を変えたら、コマンドラインでビルドして、通ることを確認してから報告する。
- エディタが開いていて Live Coding が有効だと、外からのビルドが失敗することがある。そのときはユーザーにエディタを閉じてもらうよう頼む。

## 判断に迷ったら

- 手応え・操作感・仕様の判断で迷ったら、`sakurai` スキル（桜井政博氏のゲーム制作の原則）を参照する。
- 引用するときは動画番号を添える。

## コミュニケーション

- ユーザーとのやり取りは日本語で行う。
- ユーザーは 3DCG アニメーター / リガー。アニメーションとリグの話は専門用語で通じる。C++ や UE のプログラムの話は、専門用語をかみ砕いて説明する。
